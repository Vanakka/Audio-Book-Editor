# Book Metadata Tool audit and repairs

Audit started October 5 and completed October 6, 2026 (America/New_York).

The application source at this project root was audited and repaired. The nested `Book Metadata` Git checkout was already modified when the audit began and was left untouched. Existing audiobook files, application settings, caches, and the original portable distribution were not used as test fixtures.

## Coverage and remaining limits

Source review covered core files, scrapers/HTTP/cover handling, UI workflows/workers, startup/settings, dependency manifests, launch, and packaging. No further reproduced scanner, Libation import, or model defect was found. Live provider availability and future HTML changes were not tested; scraper regressions use controlled offline responses. Cross-volume behavior was tested with a simulated EXDEV failure rather than moving real media between drives.

Unusual chapter text-track signatures may fail safely, retaining the original file. Existing CDEK-as-ASIN fallback semantics remain intentional. The audit is not a blanket assurance that all possible defects have been found.

Packaged startup is tested on this Windows host (build 26200), not a matrix of Windows versions or hardware. Windows-native ICU is documented by [Microsoft](https://learn.microsoft.com/en-us/windows/win32/intl/international-components-for-unicode--icu-). Python package advisory results do not cover every optional Qt DLL collected by the broad existing bundle specification.

The project is not registered in `Knowledge/projects/INDEX.md`. The initial audit did not create a Knowledge project registration or change sibling lanes. It prepared the source fixes and tests locally for review; subsequent GitHub publication is tracked separately through the authorized pull request.

## Issues and fixability

- Restricted sandbox could not launch the existing `.venv` base interpreter or update Git fetch metadata. Elevated commands succeeded; the environment was not broken. Verdict: accepted access requirement; use the project interpreter with the approved execution path.
- Qt test class MagicMock substitution caused a native crash; a plain method stub isolated the test correctly. Verdict: fixed test harness; full real MainWindow regressions pass.
- Multi-file patch calls sometimes applied only their first file. Every affected file was reread and missing edits applied individually. Verdict: transient tool behavior; verify resulting bytes after partial patch failures.
- Full discovery exposed old global `requests` mocking. Verdict: fixed now; keep package mocking local to individual tests.
- The packaged Qt import failure was reproduced and isolated to a colliding third-party ICU DLL from the build PATH. Verdict: packaging filter fixed; final startup result is recorded below. Optional Qt deployment/QML and unused SQL-driver dependency warnings do not represent modules used by this app; startup checks cover the application imports, not those unused features.
